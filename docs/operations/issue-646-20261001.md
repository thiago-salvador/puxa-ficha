### Trajeto da divergência

1. **Coleta:** o workflow `.github/workflows/ingest.yml` cobre os pleitos 2002 a 2024. O workflow `tse-julgamento-dry-run.yml` é manual, em dry-run e com coorte restrita; não mantém esses três registros automaticamente. A coorte pública da ferramenta de julgamento também difere da auditoria: 204 perfis contra 512 candidaturas, incluindo Senado.
2. **Persistência:** SELECT de 01/10 às 19:19:31 UTC confirmou os três escalares antigos. Os registros conservavam `status=candidato` e `publicavel=true`. As leituras atuais da API pública retornaram 200 e os mesmos valores divergentes. Os senadores têm API acessível, embora não pertençam ao conjunto `public_profiles` do snapshot auditado.
3. **Normalização:** código 2 do pacote vira `deferido`; código 14 vira `indeferido`. Isso não é o erro. O código `codigoSituacaoCandidato` do detalhe pertence a outro catálogo e não é reinterpretado como código de julgamento do pacote. Sua descrição literal fundamenta o julgamento dessa fonte.
4. **Apresentação:** o escalar combinado escondia os domínios separados. A nota de indeferimento ainda dizia “enquanto couber recurso”, sugerindo recurso sem evidência. O novo componente distingue julgamento, concorrência, flags de aptidão e recurso; cabeçalho e dados gerais usam o mesmo resolvedor.

## Implementação

Reutilizamos `situacao_candidatura` e `verificacao_campos.candidatura_situacao`; não há migração nem mudança de schema. O novo recibo contém identidade do candidato, SQ, julgamento e fontes alternativas, concorrência/aptidão, recurso e datas por fonte.

O planejador puro exige identidade por SQ/cargo/UF, valida fonte TSE, hash e timestamp, preserva os metadados anteriores e não altera `status` nem `publicavel`. Fontes divergentes só permitem metadados quando o escalar atual coincide com uma delas; caso contrário bloqueiam o plano. O resolvedor público também rejeita recibos de outra identidade, incompletos ou incompatíveis com o escalar atual. Ausência de recurso vira `Desconhecido`.

O CLI `scripts/audit/reconciliar-candidaturas-situacao-local.ts` só lê/escreve JSON local. Não importa cliente de banco e não oferece `--apply`. Seu replay opcional usa identidade exata e conserva o snapshot original. Para reproduzir o plano:

```sh
PATH=/opt/homebrew/opt/node@24/bin:$PATH node --import tsx scripts/audit/reconciliar-candidaturas-situacao-local.ts \
  --before=docs/operations/evidence/issue-646/issue-646-situacao-before-20261001.json \
  --official=docs/operations/evidence/issue-646/issue-646-situacao-fontes-20261001.json \
  --out=/tmp/issue-646-plano-reproduzido.json
```

Exit 2 é esperado pelo caso de revisão de Ricardo. Nenhum caminho de escrita remota foi acrescentado. O refresh automático de julgamentos de 2026 continua uma lacuna operacional; este pacote prepara a correção nominal para revisão.

## Limites e revisão

A ambiguidade de julgamento de Ricardo descrita nesta investigação existia no snapshot anterior às 19:51 UTC e foi resolvida pelo novo pacote, que também informa `INDEFERIDO`. `Concorrendo`, registro indeferido e as duas flags de aptidão são domínios diferentes. A ausência de campo de recurso não prova ausência de recurso. O plano atualizado preserva a exposição pública dos três e não os classifica como excluídos; flags API anteriores e textos do portal atual têm datas e fontes separadas.

A revisão do principal e do Jev foi concluída e aprovou o pacote atualizado. Commit/push/PR pertencem à fase de publicação autorizada, enquanto os resultados reais de CI, promoção Vercel, CAS do banco e verificação pública precisam constar no recibo de release. A issue permanece aberta durante essa execução.
